# FastAPI Backend Report

## 1. Architecture
The FastAPI backend is structured modularly:
- **`backend/main.py`**: Entry point and CORS configuration.
- **`backend/api/endpoints.py`**: HTTP routing logic separated from business logic.
- **`backend/services/`**:
  - `data_service.py`: Loads historical data and metadata, exposing fast dataframe queries.
  - `forecasting.py`: Manages recursive forecasting algorithms based on loaded strategy metadata.
  - `decision_engine.py`: Encapsulates business formulas (costs, returns, SELL/WAIT logic).
- **`backend/schemas/`**: Pydantic models handling request validation and structured JSON responses.
- **`backend/tests/`**: Automated pytest suite.

## 2. API Endpoints
- **`GET /api/health`**: Health check.
- **`GET /api/available-mandis`**: Lists exactly which Crop-Mandi pairs have verified models loaded.
- **`GET /api/historical-prices`**: Fetches historical time-series data for a specific pair.
- **`POST /api/forecast`**: Predicts future prices recursively using the selected model strategy.
- **`POST /api/compare`**: Evaluates transportation, returns, and provides SELL/WAIT decisions across multiple mandis simultaneously.

## 4. Forecasting Strategy & Recursive Methodology
The backend integrates the active forecasting strategy dictated by the generated metadata artifact (currently `naive` for all 5 verified pairs).
- **Recursive Logic**: For multi-month horizons where actual values are unknown, $t+1$ uses the `latest_known_price`. Subsequently, $t+n$ feeds $forecast(t+n-1)$ backward as input. The backend strictly prevents accessing future actual dataset rows.

## 5. Historical Data Coverage & Limitations
- **Constraint**: The underlying Agmarknet dataset ends in June 2017.
- **Implementation**: The backend never implies live 2026 data. Every relevant response explicitly returns `metadata.limitation` to clearly inform the frontend that forecasts are generated relative to the June 2017 cutoff point. 
- **No Fabrications**: Data is strictly drawn from `cleaned_dataset.csv`. Unverified mandis result in a 404.

## 6. Business Formulas

### Transport Cost & Unit Conversion
- **Formula**: `transport_cost = distance (km) × transport_rate (Rs/km/Quintal) × quantity (Quintals)`
- **Conversion**: If the user inputs `quantity_unit` as "tonnes", it is strictly converted: $Quintals = Tonnes \times 10$.

### Expected Net Return
- **Formula**:
  - `gross_revenue = expected_price (Rs/Quintal) × quantity (Quintals)`
  - `net_return = gross_revenue - transport_cost`
- Note: Holding costs are excluded in this version.

### Volatility
- **Methodology**: Calculates the standard deviation of month-over-month percentage returns over the last 12 available months from the historical dataset, returning a percentage value (e.g., 5.34%).

### SELL/WAIT Decision Engine
- **Logic**: The engine computes the current net return and the forecasted net return. 
- **Rule**: If the forecasted net return improves the current net return by more than a configurable threshold (default 2%), the decision is **WAIT**. Otherwise, it is **SELL**.
- **Transparency**: A `decision_reason` is appended to explain the mathematics (e.g., "Forecast net return improvement (0.00%) is below the 2.0% threshold.").

## 7. Validation & Error Handling
- **404 Not Found**: Thrown when a Crop-Mandi is unsupported, or when historical data is requested for an unknown pair.
- **422 Unprocessable Entity**: Automatically generated by Pydantic if inputs are invalid (e.g., negative distance, negative quantity, unrecognised quantity unit).

## 8. Testing Results
Automated tests executed successfully (`9 passed, 0 failed`) via `pytest backend/tests/`.
- Validated health checks, historical retrievals, and available mandi extraction.
- **Verified 3-month recursive forecasting**: Confirmed that the `naive` strategy mathematically repeats the latest known price into the horizon.
- **Verified Math**: Explicitly tested Transport conversion ($5 \text{ tonnes} = 50 \text{ quintals}$), net return mathematics, and the SELL/WAIT boolean logic boundary.

## 9. Known Limitations
- The system fundamentally assumes the `naive` strategy as optimal based on empirical data, resulting in flat multi-month forecasts.
- Does not currently integrate actual routing APIs (distances are explicitly expected to be user-provided).
- Variety mixing within a single Mandi aggregates to a single median monthly price, which could introduce noise if the proportional mix changes.
